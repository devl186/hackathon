# What I learned

After each phase, the Agent asks the developer for one useful learning and records it briefly.

- **Planning:** Check tooling first: a corporate TLS proxy blocked npm until the human fixed it — don't bypass `strict-ssl`.
- **Detection:** Lookbehind/lookahead on whole digit runs prevents partial matches (e.g. phone inside a card). Running detectors highest-risk-first with a claimed-span mask avoids double counting. Use genuinely Luhn-valid numbers for 13/20-digit boundary tests, or the test proves nothing. Masking inside the detector keeps raw values from ever leaving `scanText`.
- **Security/persistence:** Don't trust `Content-Length` or MIME: cap the body stream yourself, then validate extension, size, control bytes and strict UTF-8 on the server. `next start` binds to all interfaces by default — use `-H 127.0.0.1` for an unauthenticated route. Spying on `console.*` in tests is a cheap guard against logging uploads. A composite FK `(scan_id, user_id) → scans(id, user_id)` enforces parent-child ownership even though FK checks bypass RLS. One `SECURITY INVOKER` RPC = one transaction = atomic save with RLS still applied. Authenticate before reading the body.
- **UI:** Copy canonical `lp-*` anatomy instead of typing classes from memory, then let a test parse design.md's legal class sets and fail on anything else. Radio groups in a plain GET form gave server-validated, URL-shareable filters without fighting lepidus.js inside React. In Next 16, `middleware.ts` is `proxy.ts`; exclude upload API routes from it because the proxy buffers request bodies.
- **Testing/deployment:** Run `tsc` separately from Vitest — Vitest passed while `tsc` caught a `Uint8Array<ArrayBufferLike>` vs `BlobPart` typing error. `next build` rewrites `tsconfig.json`; rerun tests/typecheck after it. A `ReadableStream` pre-pulls one chunk at default `highWaterMark` — use `0` plus a positive control when testing "body not read". Mocked tests can't prove RLS; keep hosted tests that skip loudly when not configured. Mark fixtures `-text` in `.gitattributes` so Windows CRLF conversion can't change byte counts. A failing `beforeAll` skips every test — "0 failed" is not a pass. Negative security tests need positive controls and specific error codes, or they pass for the wrong reason (unique constraint, undefined id). Behind a TLS-intercepting proxy, `NODE_USE_SYSTEM_CA=1` fixes Node fetch without disabling verification; `strict-ssl=false` is not a fix. For CSV export, quote every field and neutralize formula triggers after stripping leading whitespace/control chars — `\t=1` and ` @x` are as dangerous as `=1`; verify with an independent parser, not the same code that wrote the CSV.
